# TravelX backend

The API reads `DATABASE_URL` from `.env.local` generated by the Neon CLI in
this folder. It also loads `.env` here as a local fallback. `.env.local` takes
precedence. Never put connection strings or credentials in
frontend files or commit them.

## Run locally

From the project root:

```powershell
npm --prefix Back-end install
npm --prefix Back-end run build
npm --prefix Back-end start
```

Open `http://localhost:3001/api/health` to verify the connected database and
catalog tables. The API also serves the built website at `http://localhost:3001`.

## Neon services

The workspace is linked to the Neon `production` branch. Neon Managed Auth is
enabled there; `neon deploy` pulls its public Auth base URL into the ignored
`.env.local`. The API returns that URL via `GET /api/config`; it does not
expose database credentials or private keys. The frontend uses the official
`@neondatabase/neon-js/auth` client for sign-up, sign-in, session restoration,
and sign-out.

The development branch is `travelx-dev`; it is configured locally in the ignored
`.neon` and `.env.local` files. The schema and seed data are managed by numbered
SQL files under `db/`. Run `npm run db:migrate` to apply any unapplied files.
Neon Auth credentials stay in its managed `neon_auth` schema. App profiles,
bookings, favorites, and newsletter subscriptions use the public schema.

## API routes

- `GET /api/health`
- `GET /api/config`
- `GET /api/destinations`
- `GET /api/trips`

Run tests from the project root with `npm --prefix Back-end test`, or from
this directory with `npm test`.
